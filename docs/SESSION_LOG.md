## Session 3 — 2026-09-26 — Notification survey and ingestion architecture decisions

The session began by tidying Git after pull request #3: switching to `main`, pulling, and deleting the merged branch locally and its stale remote reference. On the operator's explicit request, Bank A's notification emails were surveyed locally. A header-only inventory listed the message types, a few samples were stored as `.eml` files in the ignored `data/raw/` directory, and a full in-memory scan confirmed that every transaction notification matches one of three sentence patterns: credit-card purchase, account purchase, and ATM withdrawal. The scan also found two currency formats and no reversal notifications. A handful of legitimate messages failed SPF but passed DMARC, so authenticity checks will require DMARC. `TRANSACTION_CASES.md` and `THREAT_MODEL.md` now reflect these findings without naming the institution or quoting its wording. New decisions record: surveying formats before defining the transaction model; polling first, then Pub/Sub, then a webhook; local execution before any cloud hosting; PostgreSQL as the transactional database; pseudonymous institutions with a generic parser driven by local provider profiles; and keeping the repository public, with a private companion repository as a future option. Next session: Bank A's PDF account statements for backfill, reconciliation, and installment tracking.
